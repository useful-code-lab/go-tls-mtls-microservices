# Go TLS/mTLS: защищённое взаимодействие микросервисов 🛡️

Практический пример того, как **защитить взаимодействие микросервисов на Go с помощью TLS и mTLS**.

Проект можно использовать как учебный стенд, основу для собственного сервиса или готовую шпаргалку при настройке HTTPS и взаимной аутентификации между сервисами.

## 🎯 Что вы получите из проекта

После изучения проекта вы сможете:

* понять разницу между обычным TLS и mTLS;
* настроить HTTPS-сервер на Go;
* создать локальный Центр сертификации (CA);
* выпускать сертификаты для серверов и клиентов;
* настроить проверку сертификата сервера;
* настроить обязательную проверку сертификата клиента;
* подключаться к mTLS-сервису из Go;
* проверять mTLS-соединение через `curl`;
* увидеть на практике, почему обычный HTTPS-клиент не может подключиться к mTLS-серверу;
* использовать проект как основу для экспериментов с безопасным взаимодействием микросервисов.

---

## 🔐 Что такое TLS и mTLS

Проект показывает два уровня защиты.

### Уровень 1 — TLS

TLS шифрует соединение между клиентом и сервером.

Сервер предъявляет свой сертификат, а клиент устанавливает защищённое HTTPS-соединение.

Схематично:

```text
Client ──────── TLS ────────> Server
                🔒
```

Такой подход подходит, когда сервер необходимо защитить от перехвата трафика, но идентификация клиента на уровне сертификата не требуется.

### Уровень 2 — mTLS

mTLS (Mutual TLS) добавляет взаимную аутентификацию.

Теперь сертификат предъявляют обе стороны:

```text
Client ──────── TLS ────────> Server
  │                             │
  └──── client certificate ─────┘
  
  Server certificate
        ↓
  проверяется клиентом
```

Сервер проверяет сертификат клиента, а клиент проверяет сертификат сервера.

Это позволяет использовать сертификаты как дополнительный механизм идентификации сервисов.

## 🚀 Зачем запускать этот проект

Проект особенно полезен, если вы:

* изучаете безопасность микросервисов;
* разрабатываете backend на Go;
* хотите разобраться с TLS на практике, а не только в теории;

* хотите понять принцип работы mTLS;
* готовите инфраструктуру, где сервисы должны аутентифицировать друг друга;

Вместо абстрактной конфигурации здесь можно последовательно пройти весь путь:

Для запуска потребуется:

```bash
go version
```

Проверить OpenSSL:

openssl version

## 🔑 1. Генерация сертификатов

Перед запуском необходимо создать локальный Центр сертификации и сертификаты для сервера и клиента.

Запустите:

```bash
bash certs/gen.sh
```

После выполнения необходимые файлы появятся в каталоге:

```text
certs/
```

Приватные ключи не должны попадать в Git и добавлены в `.gitignore`.

---

# 🛡️ 2. Базовый TLS

Начнём с обычного HTTPS.

Сервер предоставляет сертификат, а соединение между клиентом и сервером шифруется.

## Запуск сервера

```bash
go run cmd/server/server.go
```

Сервер будет доступен по адресу:

```text
https://localhost:8443
```

## Быстрая проверка через cURL

Для локального тестирования можно отключить проверку сертификата:

```bash
curl -k https://localhost:8443/api/data
```

Ожидаемый ответ:

```json
{
  "status": "secure",
  "message": "Данные переданы через TLS"
}
```

> `-k` отключает проверку сертификата сервера. Такой режим удобен для локального эксперимента, но не является рекомендуемой настройкой для production.

---

## Проверка через Go-клиент

Запустите:

```bash
go run cmd/client/client.go
```

Клиент получит ответ:

```text
✅ Ответ сервера: {"status": "secure", "message": "Данные переданы через TLS"}
```

Этот клиент демонстрирует вариант подключения, аналогичный `curl -k`, с отключением проверки сертификата сервера.

---

# 🔒 3. Взаимный TLS — mTLS

Теперь включим взаимную аутентификацию.

В режиме mTLS сервер не только шифрует соединение, но и **требует сертификат клиента**.

Используется режим:

```go
RequireAndVerifyClientCert
```

Схема взаимодействия:

```text
             ┌──────────────────────┐
             │       TLS/mTLS       │
             │                      │
Client  ◄────┤  Сервер проверяет    │
 certificate │  сертификат клиента  │
             │                      │
Server  ─────┤  Клиент проверяет    │
 certificate │  сертификат сервера  │
             └──────────────────────┘
```

---

## Запуск mTLS-сервера

```bash
go run cmd/mtls/server/server.go
```

Сервер будет доступен по адресу:

```text
https://localhost:8443
```

---

## ❌ Что произойдёт без сертификата клиента

Попробуйте выполнить обычный запрос:

```bash
curl -k https://localhost:8443/api/data
```

Сервер отклонит соединение.

Например:

```text
curl: (35) error... alert bad certificate
```

Это ключевой эксперимент проекта:

**`-k` отключает проверку сертификата сервера, но не заменяет клиентский сертификат.**

---

# ✅ 4. Подключение mTLS-клиента

Теперь используем клиентский сертификат.

Запустите:

```bash
go run cmd/mtls/client/client.go
```

Клиент:

1. предъявляет `client.crt`;
2. использует `client.key`;
3. проверяет сертификат сервера;
4. использует `ca.crt` для проверки доверия.

Ожидаемый результат:

```text
✅ Успех mTLS! Ответ сервера:
{"status": "mTLS Success", "client": "GuardGo-Client"}
```

---

# 🧪 5. Проверка mTLS через cURL

То же самое соединение можно проверить без Go-клиента.

Необходимо передать сертификат и приватный ключ клиента:

```bash
curl -k \
  --cert certs/client.crt \
  --key certs/client.key \
  https://localhost:8443/api/data
```

В этом случае сервер получает необходимый клиентский сертификат и может выполнить его проверку.

---

# 🔍 TLS vs mTLS

| Возможность                      | TLS | mTLS |
| -------------------------------- | --: | ---: |
| Шифрование трафика               |   ✅ |    ✅ |
| Сервер имеет сертификат          |   ✅ |    ✅ |
| Клиент проверяет сервер          |  ✅* |    ✅ |
| Сервер проверяет клиента         |   ❌ |    ✅ |
| Клиентский сертификат обязателен |   ❌ |    ✅ |
| Взаимная аутентификация          |   ❌ |    ✅ |

* В проекте базовый Go-клиент специально демонстрирует вариант с отключённой проверкой сертификата для локального эксперимента.

* `cmd/mtls/server/` — сервер с обязательной проверкой клиентского сертификата;
* `cmd/mtls/client/` — клиент с сертификатом и проверкой CA.
